\begin{abstract}
Previous work showed that classical statevector simulation of Grover's algorithm reached a memory limit at approximately $n=31$--$32$ qubits on GPU hardware. This project investigates whether tensor networks can provide a more memory-efficient alternative. The implementation uses the \texttt{quimb}, \texttt{cotengra}, and \texttt{kahypar} Python libraries instead of the NVIDIA cuTensorNet backend originally proposed.

The study measures three related properties of the tensor-network representation: the estimated memory required for exact contraction, the bond dimension needed for exact MPS convergence, and the difference between estimated and measured memory during real contractions.

The main findings are: (1) tensor networks did not provide a sustained memory advantage over statevector simulation for the tested range $n=2$--$11$; (2) the minimum bond dimension for exact convergence increased from 4 to 32 between $n=5$ and $n=11$; and (3) measured memory was substantially larger than the simple width-based estimate, showing that theoretical contraction metrics do not directly predict practical memory usage.

Overall, the experiments suggest that Grover's circuit is not a particularly favorable example for tensor-network compression at the sizes tested. The results are limited to the implementation and range studied, but they provide a useful example of how entanglement can reduce the practical advantage expected from tensor-network methods.
\end{abstract}

\section{Introduction}

Classical simulation of an $n$-qubit quantum state with a full statevector requires storing $2^n$ complex amplitudes. Previous work on Grover's algorithm (BSP2) demonstrated this limitation experimentally, reaching approximately $n=31$--$32$ qubits on GPU hardware before running out of memory. This motivates the question of whether a different representation of the same quantum state can reduce the practical cost.

Tensor networks provide one possible approach. Instead of storing all $2^n$ amplitudes explicitly, a large tensor can be factorized into a network of smaller tensors. The benefit depends on the structure of the state or circuit: when the required intermediate tensors or MPS bond dimensions remain small, the representation can be much more compact than a full statevector. TensorNetwork.org describes an MPS as a chain of smaller tensors connected by bond indices, with the bond dimension controlling the expressiveness of the representation \cite{TensorNetworkMPS}.

Grover's algorithm is useful for testing this idea because its circuit contains a structured oracle and diffusion operator, but its operation also creates global interference across the search space. The goal of this project is therefore not to assume that tensor networks will work better, but to measure whether they actually provide an advantage for this particular algorithm.

\subsection{Change of Backend}

The original proposal specified NVIDIA cuTensorNet on GPU hardware. During implementation, the project instead used the CPU-based \texttt{quimb} + \texttt{cotengra} + \texttt{kahypar} stack. This was mainly a practical implementation decision: the chosen libraries made it possible to inspect contraction paths and perform the MPS experiments within the available development environment. The resulting comparison should therefore be understood primarily as a comparison of simulation methods, rather than a hardware-to-hardware benchmark.

The project uses three main libraries:
\begin{enumerate}
  \item \textbf{quimb} (QUantum Information Many-Body): A Python library for tensor network operations, including quantum circuit evaluation via tensor contraction and via approximate matrix product state (MPS) simulation with a truncation parameter.
  \item \textbf{cotengra} (Contraction Engine): A library that searches for good contraction orderings for tensor networks using randomized, hyperparameter-tuned heuristics (finding the truly optimal ordering is NP-hard in general).
  \item \textbf{kahypar}: A hypergraph partitioner that \texttt{cotengra} can optionally use internally as one of its candidate methods for finding contraction orderings, alongside a simpler greedy method.
\end{enumerate}

We address three research questions: (1) At what qubit count, if any, do tensor networks become more memory-efficient than statevector simulation? (2) How does the minimum bond dimension (a measure of entanglement in tensor decompositions) scale with qubit count? (3) At what qubit count does the tested tensor-network simulation become practically infeasible, and what observations help explain this behavior?

The rest of this report is organized as follows. Section~2 introduces Grover's algorithm, tensor networks, and MPS bond dimension. Section~3 gives the relevant library and research context. Section~4 describes the implementation and experiments. Section~5 presents the results, and Section~6 discusses their interpretation. Section~7 highlights avenues for future work, and the report ends with the main conclusions in Section~8.

\section{Theoretical Background}

\subsection{Grover's Algorithm}

We assume familiarity with Grover's algorithm from prior work. Briefly: given a Boolean oracle marking exactly one target state $|x^*\rangle$ in a search space of $N = 2^n$ states, Grover's algorithm uses repeated oracle-diffusion cycles to amplify the target's amplitude. After $k_{\text{opt}} = \lfloor\frac{\pi}{4}\sqrt{N}\rfloor$ iterations, measurement yields $|x^*\rangle$ with high probability. The algorithm is implemented as $n$ Hadamard gates (initialization), followed by $k_{\text{opt}}$ iterations of (1) a phase oracle and (2) a diffusion operator.

\subsection{Tensor Networks and Contraction}

A quantum circuit can be represented as a tensor network: each quantum gate is a tensor (a multi-dimensional array), and evaluating the circuit means contracting the network (summing over shared indices).

\textbf{Tensor definition.} A tensor is a multi-dimensional array. A single-qubit gate is a $2 \times 2$ matrix (a rank-2 tensor); a two-qubit gate is $2 \times 2 \times 2 \times 2$ (rank-4).

\textbf{Contraction.} If tensor $A$ has shape $(d_a, d_b, d_c)$ and tensor $B$ has shape $(d_b, d_d)$, their contraction along the shared index $d_b$ produces a tensor $C$ of shape $(d_a, d_c, d_d)$:
\[
C_{a,c,d} = \sum_{b} A_{a,b,c} \cdot B_{b,d}
\]

\textbf{Contraction path.} The order in which pairs of tensors are contracted determines both the memory cost (the size of intermediate tensors created during contraction) and the time cost (the number of scalar multiplications). Finding the truly optimal contraction path is NP-hard in general; \texttt{cotengra} instead runs a bounded, randomized search over candidate orderings and returns the best one found within a time/repeat budget. As discussed in Section~4, this search is stochastic and can return different-quality orderings across repeated runs on the same circuit, particularly for larger, more heavily decomposed circuits.

\textbf{Contraction width ($W$).} We define
\[
W = \log_2 \left( \max_{s} \, |T_s| \right)
\]
where $|T_s|$ is the size of the intermediate tensor created at contraction step $s$. $W$ measures peak memory during contraction, expressed in qubits' worth of dimension, directly comparable to the statevector's $\log_2(2^n) = n$.

\textbf{Contraction cost ($C$).} $C$ is $\log_{10}$ of the estimated total number of scalar multiplication operations across all contraction steps, for the chosen ordering.

\subsection{Bond Dimension and Entanglement}

An alternative approach to exact contraction is to approximate the state as a Matrix Product State (MPS), where the state is decomposed into a chain of small tensors connected by bonds, each with a bond dimension $\chi$ controlling both compression and accuracy.

\textbf{Bond dimension definition.} If the state is partitioned into left and right halves via singular value decomposition (SVD), the bond dimension is the number of singular values kept. Keeping all singular values gives an exact representation; truncating to the $\chi$ largest is a lossy compression. The minimum $\chi$ for which truncation loses no information (to numerical precision) is what we measure and report.

\textbf{Connection to entanglement.} For a bipartition of a quantum state, the Schmidt rank is related to the MPS bond dimension. In particular, the entanglement entropy is bounded by $\log_2 \chi$. A product state has $\chi=1$, while an arbitrary $n$-qubit state may require a bond dimension as large as $2^{\lfloor n/2 \rfloor}$ for an appropriate bipartition \cite{TensorNetworkMPS}. Therefore, increasing bond dimension provides a practical indication that the state is becoming harder to compress as an MPS.

\subsection{Why Tensor Networks Can Fail for General Circuits}

Two mechanisms can defeat tensor-network compression for a given circuit: (1) genuine entanglement growth, where the required bond dimension approaches $2^{n/2}$ regardless of contraction strategy, and (2) contraction path cost, where even a circuit with bounded entanglement can still be expensive to contract if a good ordering is hard to find or if gate decomposition inflates the network's structure. Section~5 presents evidence for both mechanisms in this project's data.

\section{Related Work and Library Context}

\textbf{Tensor network simulation.} Markov and Shi~\cite{Markov2008} established that contracting a tensor network computes quantum circuit amplitudes, and that circuits with bounded treewidth admit efficient (polynomial-time) contraction.

\textbf{Contraction heuristics.} Finding optimal contraction paths is NP-hard in general. \texttt{cotengra}~\cite{cotengra} uses randomized, hyperparameter-tuned heuristics, optionally including hypergraph-partitioning-based methods via \texttt{kahypar}~\cite{kahypar}, to find good (not necessarily optimal) paths without exhaustive search.

\textbf{Quantum simulation libraries.} \texttt{quimb}~\cite{quimb} is a widely-used Python library for tensor-network quantum simulation, used here both for exact contraction (via its \texttt{cotengra} integration) and for approximate MPS simulation with explicit bond-dimension truncation.

\textbf{Grover studies.} Prior experimental work on Grover's algorithm has focused on hardware demonstrations at small qubit counts or classical statevector simulation (as in BSP2). This project extends that line of work with a systematic tensor-network-based study.

\section{Implementation and Methodology}

\subsection{Circuit Construction and Transpilation}

Grover's algorithm is constructed in Qiskit (reusing the oracle and diffuser construction from BSP2) and converted for use with \texttt{quimb} via the \texttt{qiskit-quimb} bridge. This bridge only recognizes elementary single- and two-qubit gates; Grover's oracle and diffuser use an arbitrary-arity multi-controlled-X gate (\texttt{mcx}), which Qiskit's simulator handles natively but the bridge does not. The circuit is therefore transpiled to a basis of \texttt{rz}, \texttt{sx}, \texttt{x}, and \texttt{cx} gates before conversion, which recursively decomposes each \texttt{mcx} into a chain of smaller gates. This decomposition is treated as a genuine part of the cost being measured, not a workaround to be discounted: it is the same gate-count blowup any concrete backend would face when asked to execute an $n$-controlled gate using only elementary two-qubit interactions.

\subsection{Search Stability of the Contraction Optimizer}

\texttt{cotengra}'s randomized search (\texttt{HyperOptimizer}) can produce varying contraction width estimates across repeated runs on the same circuit, particularly for $n \ge 9$. To mitigate this variance, the search was run multiple independent times per qubit count, keeping the minimum width found (three repeats for $n \le 9$; a single run for $n=10,11$ due to the search taking tens of minutes to hours). Repeated multi-trial search was used by default throughout, as single-shot greedy search proved unstable and occasionally returned implausibly poor orderings for larger circuits.

\subsection{Bond Dimension Measurement via MPS Truncation}

For each qubit count $n$ and a set of randomly chosen target states, we run the Grover circuit through \texttt{quimb}'s MPS circuit simulator at a range of fixed maximum bond dimensions $\chi \in \{2, 4, 6, 8, 10, 12, 16, \allowbreak 20, 24, 28, 32, 48, 64\}$, and separately with $\chi$ uncapped as an exact reference. For each $\chi$, we compare the resulting amplitude for the target bitstring against the uncapped reference amplitude, and record the smallest $\chi$ at which the error drops to (and stays at) zero to numerical precision. This is repeated for three independent random target states per $n$; we report both the worst-case (maximum) and best-case (minimum) threshold across those three targets, since different target states can require different bond dimensions.

We note that this MPS-based approach is conceptually distinct from the exact-contraction approach used for $W$ and $C$ above: MPS truncation is lossy by construction (bond dimension is an approximation parameter), while the contraction-width approach is always exact. The two therefore answer different aspects of the same underlying research questions and are reported as separate, complementary results rather than one extending the other.

\subsection{Real Memory Measurement}

For small $n$ (up to $n=9$), we additionally perform the tensor-network contraction for real (not just estimating its cost) and measure peak memory using Python's \texttt{tracemalloc} module, which tracks memory allocated through Python's memory allocator (this captures NumPy array allocations on standard builds, but can undercount memory allocated outside the Python allocator, such as some BLAS working buffers). To avoid wasting compute on contractions that would be infeasible to actually run, we only attempt real execution when the rehearsed width estimate implies a feasible memory footprint (below roughly 2\,GB); the $n=10,11$ points in the main sweep, whose estimated widths implied far larger footprints, were excluded from this real-execution comparison for that reason.

\subsection{Experimental Setup}

To evaluate the tensor network representations systematically, experiments were structured as follows: For each qubit count $n$, the same Grover circuit was constructed, transpiled, and converted into a tensor network. The contraction optimizer was then used to find a contraction path. From this path, the maximum intermediate tensor size (width $W$) and estimated contraction cost were recorded. Separately, the identical circuit was simulated as an MPS with different maximum bond dimensions.

The experiments measured scaling from $n=2$ up to $n=11$. Three random target states were tested for the bond-dimension experiments to capture variation, while other structural tests relied on a single representative target or randomized contraction paths. Real execution and memory tracking were conducted up to $n=9$. Estimated paths were pushed to $n=11$, beyond which the contraction optimizer itself became too computationally expensive to run reliably within the project's constraints.

Therefore, the expected theoretical advantage of tensor networks does not appear for this circuit. This directly answers research question~1: in the range tested, tensor networks do not become more memory-efficient than statevector simulation for Grover's algorithm; if anything, the gap runs strongly in the opposite direction and widens with $n$.

\textbf{Key finding}: real measured memory substantially exceeds the width-based estimate throughout this range — by roughly three orders of magnitude at small $n$, narrowing to roughly one to two orders of magnitude by $n=9$. This is expected, not anomalous: $W$ by definition captures only the size of the single largest intermediate tensor at any one contraction step, not the total memory footprint of the whole contraction process (which involves multiple coexisting tensors, plus NumPy/\texttt{quimb}/Python object overhead). This is an important methodological finding in its own right: the $16 \cdot 2^W$ formula should be read as a lower bound on required memory, not a tight prediction of actual usage.

\section{Analysis and Discussion}

\subsection{Why Tensor Networks Struggle for Grover's Algorithm}

Two related factors, both visible in the data above, work against tensor-network compression for this circuit:

\textbf{1. Increasing representation complexity.} Figure~8 shows that the bond dimension required for exact MPS convergence increases with $n$. This is consistent with the idea that a larger bond dimension is needed when the state contains more correlations across the chosen bipartitions. The experiment does not by itself prove a specific entanglement mechanism, but it shows that the MPS representation becomes less compact as the circuit grows.

\textbf{2. Gate-count increase from transpilation.} As described in Section~4.1, the \texttt{mcx} decomposition required for tensor-network compatibility increases the number of elementary gates. This makes the tensor network larger and can make contraction-path search more difficult, even before considering the bond dimension of the resulting state.

Together, these observations help explain why the tested tensor-network approach did not outperform statevector simulation for Grover's algorithm. They should not be interpreted as a general limitation of tensor networks. Their effectiveness depends strongly on the structure of the circuit and on whether the resulting tensors remain sufficiently small.

\subsection{Limitations}

Several methodological limitations restrict the generalizability of these findings:

\textbf{Hardware:} The tensor-network experiments were CPU-based, while the BSP2 statevector result used GPU hardware. Thus, the results demonstrate that this specific CPU tensor-network implementation did not outperform the previous GPU statevector implementation, rather than definitively proving tensor networks are universally worse than statevectors on equivalent hardware.

\textbf{Small qubit range:} The tensor-network experiments only reached $n=11$. This restricted scale does not allow for definitive claims about the asymptotic behavior of arbitrarily large Grover circuits.

\textbf{Random target states:} The bond-dimension experiment utilized three random target states per $n$. While reasonable for an initial empirical estimate, three samples are insufficient to fully characterize the behavior of every possible target state in the search space.

\textbf{Contraction optimizer randomness:} As noted in Section 4.2, the heuristic search for contraction paths introduces variance, meaning the recorded memory estimates reflect the best path found within the search budget rather than the guaranteed theoretical minimum.

\textbf{Memory measurement:} The use of \texttt{tracemalloc} captures memory allocated through Python's allocator, but does not capture external memory such as certain low-level C or BLAS working buffers, rendering it a lower bound on the true memory footprint.

\subsection{Practical Ceiling Reached in This Project}

Real contraction was only feasible up to $n=9$; single-search estimates were obtained up to $n=11$ before search cost (tens of minutes to hours per contraction attempt) made going further impractical within this project's scope. This ceiling is itself a data point: it is well short of BSP2's statevector ceiling of $n=31$--$32$ on GPU hardware, and directly reflects the entanglement-growth and search-instability findings above rather than being a separate, unrelated limitation.

\section{Future Work}

Several natural extensions to this project could provide a more comprehensive comparison of the representation methods:

\textbf{GPU tensor-network simulation:} Since the original proposal was based on NVIDIA cuTensorNet, a natural next step would be to repeat the experiments using cuTensorNet on GPU hardware and determine whether GPU acceleration changes the practical crossover point or extends the feasibility limit.

\textbf{Different algorithms:} Testing the same methodology on circuits that are more naturally suited to tensor networks (e.g., shallow circuits, low-entanglement circuits, or 1D quantum circuits) would help answer whether the scaling difficulties are inherent to tensor networks generally, or specifically tied to Grover's circuit.

\textbf{Better contraction optimization:} Investigating whether a larger search budget or different hypergraph contraction heuristics produce significantly better contraction paths could be explored to see if it lowers the theoretical memory ceiling observed for $n \ge 10$.

\textbf{Larger qubit counts:} If better hardware or GPU acceleration were available, the experiments could be extended well beyond $n=11$ to verify if the observed scaling trends hold true at larger sizes.

\section{Conclusion}

This project implemented and evaluated a tensor-network simulation of Grover's algorithm using \texttt{quimb}, \texttt{cotengra}, and \texttt{kahypar}. The experiments measured estimated memory, bond dimension, and practical contraction behavior for $n=2$--$11$ qubits.

\begin{enumerate}
  \item \textbf{At what qubit count do tensor networks become more memory-efficient?} None found in the tested range; by $n=11$ tensor-network memory estimates exceed statevector memory by roughly six to seven orders of magnitude, with the gap widening as $n$ increases.
  \item \textbf{How does bond dimension scale?} It grows with $n$, from $\chi=4$ at $n=5$ to $\chi=32$ at $n=11$, most sharply between $n=10$ and $n=11$.
  \item \textbf{Where and how does contraction become intractable?} Practically, real contraction was only feasible to $n=9$ on the hardware used, and single-search estimates only to $n=11$; the observations in Figure~9 demonstrate a sharp threshold-like convergence behavior in bond dimension, which contributes to the difficulty of scaling the simulation.
\end{enumerate}

Overall, the results suggest that the tested tensor-network representation is not advantageous for Grover's algorithm in this range. This should not be taken as a general failure of tensor networks. Rather, it illustrates an important limitation: their practical advantage depends on the circuit producing a representation with sufficiently small intermediate tensors or bond dimensions.
